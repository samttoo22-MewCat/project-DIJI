# 建立角色使用者流程實測

日期：2026-11-01。使用已登入的 Edge、真實模型連線與獨立的虛構測試角色；既有角色未刪改。

最初流程的 90 項測試與問題記錄如下；本日後續已加入伺服器草稿保存與試聊，以文末增補為準。

## 實際操作

1. 輸入台南古書修復師的概念，選 DeepSeek V4.1 Flash，開啟網路參考、關閉成人分類。重新載入後概念與模型選擇仍在。
2. 真實生成完成，進入可編輯審核頁。此輪的四次生成呼叫成功；不將單純 UI 預覽當作模型成功。
3. 修改角色名稱、簡介與背景，在背景加入可核對的虛構書籤設定，明確保存。
4. 保存完成顯示僅自己可見，伺服器確認角色在帳號私人目錄且不在共用角色庫，完整 prompt 含修改內容與 ROLEPLAY_CONTRACT。
5. 從完成畫面開啟對話，關閉成人內容並使用短對話提問。真實回覆答出新加入的唯一書籤設定，證明審核修改進入實際互動。
6. 手機版搜尋角色，顯示私有紫色卡與「我的角色 · 僅自己可見」；重新載入後角色仍可找到。空白概念被必填驗證攔下，沒有發送生成請求。375px 沒有橫向溢出。

## 發現與修正

- 模型選單原先以第一個項目作預設：改為優先 DeepSeek V4.1 Flash，保留個人暫存選擇。
- 保存後概念會在 beforeunload 被重新寫回：改為完成後不再保存舊概念，隱藏完成表單並提供「建立另一位角色」。
- 未保存草稿缺少清楚的離頁提醒：增加可見警示及瀏覽器離頁保護；沒有新增伺服器自動備份。
- 重新生成失敗可覆寫全域 draft：回應成功且驗證完整後才替換，失敗保留既有審核修改，非 JSON 錯誤顯示可理解訊息。
- 四階段生成的分類、嗜好與一句話介紹原先未保存：新增 generation_metadata，審核可修改並在保存後保留，不改既有 prompt 組裝。
- 概念暫存原先不分帳號：改為登入後依帳號恢復，登出清空畫面，舊不分帳號鍵不會自動帶入。
- 登入完成早於 creator script 時會漏接事件，模型選單永久讀取中：加入已登入狀態的立即初始化。Edge 重整實際重現；隔離 DOM 測試在修正前失敗，修正後通過。

## 驗證與界線

90 項 pytest 通過，包含私人角色隔離與審核內容重組。隔離 DOM 測試驗證防重複保存、預設模型、離頁提醒、重新生成失敗保留修改、補充資料保存、完成後重設，以及不同帳號概念不混用。

真實生成與聊天是在修正前跑完主要流程；修正後的補充資料、失敗情境與保存完成畫面以隔離測試驗證，沒有為驗證重複再付費生成一次。新版入口、必填、手機版與角色重新載入有在 Edge 讀回。

完整人設欄位仍多，適合細節調整，首次使用者的審核負擔偏高。這次保留完整欄位與可展開區塊，尚未另做簡易／進階審核模式。後續已加入伺服器草稿恢復；尚未同步的修改仍可能在離頁或崩潰後失去，伺服器保存也不等於異地備份。

## 後續增補：草稿試聊與返回

- 審核最底部新增「測試對話」，明確保存仍是另一個按鈕。試聊先同步草稿，再使用原聊天流程；資料寫入帳號獨立的 creator_trials，而非正式聊天／記憶。
- Edge 真實生成「墨禾」測試草稿，改名為「試聊測試・墨禾」，在背景加入唯一書籤暗號「青瓷試聊1101」。短對話實際回覆命中暗號，證明使用修改後的人設；第二回合生成中按返回，名稱、背景與已展開欄位均保留。
- 伺服器讀回兩回合均完成，沒有將草稿寫入私人角色庫，也沒有建立正式對話檔。未保存的草稿仍可重新載入後恢復；試聊則重新開啟新會話，不承諾在 UI 恢復過去的試聊。
- 375／768／1024／1440px 沒有橫向溢位，桌面審核按鈕同高 52px，手機返回按鈕至少 44px。手機捲到底曾發現返回按鈕被頂部導覽部分遮住，修正內層 overflow 後，按鈕完整位於導覽下方。
- 100 項 pytest 通過，新增帳號／草稿版本隔離、已保存草稿拒絕試聊、跨草稿會話拒絕、長短對話與正式 prompt 常數、伺服器歷史及試聊儲存隔離測試。隔離 DOM 測試涵蓋生成中返回、欄位／展開狀態保留、不自動保存角色、修改後新試聊。
